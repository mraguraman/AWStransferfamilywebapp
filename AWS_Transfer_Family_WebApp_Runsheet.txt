────────────────────────────────────────────────────────────────────────────────
 1. OBJECTIVE
────────────────────────────────────────────────────────────────────────────────

  Allow internet users to upload and download files to an S3 bucket using a
  browser-based interface, without any SFTP client. Authentication is handled
  by AWS IAM Identity Center (SSO). File access is controlled per-user via
  Amazon S3 Access Grants.


────────────────────────────────────────────────────────────────────────────────
 2. ARCHITECTURE
────────────────────────────────────────────────────────────────────────────────

  Internet Users (Browser)
          │
          ▼
  AWS Transfer Family Web App  (HTTPS public endpoint)
          │
          ▼
  IAM Identity Center  (User authentication / SSO)
          │
          ▼
  S3 Access Grants  (Per-user access control)
          │
          ▼
  S3 Bucket  (File storage — ap-southeast-1)

 7. DEPLOYMENT STEPS
────────────────────────────────────────────────────────────────────────────────

  Step 1 — Configure terraform.tfvars
  ─────────────────────────────────────
  Copy terraform.tfvars.example to terraform.tfvars and fill in values.

  Key fields:
    aws_region                = "ap-southeast-1"
    project_name              = "secure-transfer"
    environment               = "dev"
    web_app_provisioned_units = 1          # 1 unit = 250 concurrent sessions
    transfer_users            = [...]      # List of users to create

  User format:
    {
      display_name = "John Doe"
      user_name    = "john.doe"
      email        = "john.doe@example.com"
      given_name   = "John"
      family_name  = "Doe"
    }

  Step 2 — Initialize Terraform
  ─────────────────────────────────────
    cd terraform
    terraform init

  Step 3 — Preview Changes
  ─────────────────────────────────────
    terraform plan

  Step 4 — Deploy
  ─────────────────────────────────────
    terraform apply -auto-approve

  Step 5 — Get Web App URL
  ─────────────────────────────────────
    terraform output web_app_url

  Step 6 — User First Login
  ─────────────────────────────────────
  After apply, each user receives an AWS invitation email asking them to
  set their password. Once set, they visit the Web App URL and log in with
  their username and password.

 8. IAM ROLE CONFIGURATION (CRITICAL — DO NOT CHANGE)
────────────────────────────────────────────────────────────────────────────────

  8a. Web App Role (Identity Bearer Role)
  ─────────────────────────────────────────
  Name: secure-transfer-transfer-web-app-role

  Trust Policy:
    Principal : transfer.amazonaws.com
    Actions   : sts:AssumeRole, sts:SetContext     ← sts:SetContext is REQUIRED

  Inline Policy (AllowS3AccessGrants):
    s3:GetDataAccess              — lets web app call S3 Access Grants
    s3:ListCallerAccessGrants     — lists grants for the current user
    s3:ListAccessGrantsInstances  — discovers the Access Grants instance
    Resource: *

  COMMON MISTAKE: Using s3:ListAccessGrants + s3:ListAccessGrantsLocations
  instead of s3:ListCallerAccessGrants + s3:ListAccessGrantsInstances.
  These are DIFFERENT actions. The wrong ones cause "application setup" error.

  8b. S3 Access Grants Location Role
  ─────────────────────────────────────
  Name: secure-transfer-s3-access-grants-role

  Trust Policy:
    Principal : access-grants.s3.amazonaws.com
    Actions   : sts:AssumeRole, sts:SetContext     ← sts:SetContext is REQUIRED

  COMMON MISTAKE: Using sts:SetSourceIdentity instead of sts:SetContext.
  sts:SetContext is what S3 Access Grants uses to propagate user identity
  into temporary credentials.

  Inline Policy:
    s3:GetObject, s3:PutObject, s3:DeleteObject
    s3:ListBucket, s3:GetBucketLocation
    s3:GetObjectVersion, s3:DeleteObjectVersion
    Resource: bucket ARN + bucket ARN/*


────────────────────────────────────────────────────────────────────────────────
 9. S3 CORS CONFIGURATION (REQUIRED)
────────────────────────────────────────────────────────────────────────────────

  The S3 bucket MUST have a CORS rule that allows the Transfer Family Web App
  URL as the AllowedOrigin. Without CORS, the browser will block all S3
  requests and the app will show "application setup" error.

  CORS Rule Applied:
    AllowedOrigins : https://webapp-e552e259e7694c778.transfer-webapp.ap-southeast-1.on.aws
    AllowedMethods : GET, PUT, POST, DELETE, HEAD
    AllowedHeaders : *
    MaxAgeSeconds  : 3000
    ExposedHeaders : last-modified, content-length, etag, x-amz-version-id,
                     content-type, x-amz-request-id, x-amz-id-2, date,
                     x-amz-cf-id, x-amz-storage-class,
                     access-control-expose-headers

  IMPORTANT: Do NOT include a trailing slash on the AllowedOrigin URL.
  ✓ Correct : https://webapp-xxx.transfer-webapp.ap-southeast-1.on.aws
  ✗ Wrong   : https://webapp-xxx.transfer-webapp.ap-southeast-1.on.aws/


────────────────────────────────────────────────────────────────────────────────
 10. USER ACCESS — HOW IT WORKS
────────────────────────────────────────────────────────────────────────────────

  For each user, 4 resources must exist:

    1. aws_identitystore_user          — User account in IAM Identity Center
    2. aws_ssoadmin_account_assignment — Assigns permission set to user for AWS account
    3. aws_ssoadmin_application_assignment — Assigns user to Transfer Family
                                             Web App SSO application
                                             (without this: "You do not have
                                             access to this application")
    4. aws_s3control_access_grant      — Grants READWRITE access to the S3
                                         bucket via S3 Access Grants
                                         (without this: "application setup" error)

  All 4 are created automatically for each user in transfer_users variable.

 12. ISSUES ENCOUNTERED AND FIXES APPLIED
────────────────────────────────────────────────────────────────────────────────

  Issue 1 — Terraform schema error: identity_center_config block not found
  ─────────────────────────────────────────────────────────────────────────
  Cause   : identity_center_config must be NESTED inside identity_provider_details
  Fix     : Changed from:
              resource "aws_transfer_web_app" { identity_center_config { ... } }
            To:
              resource "aws_transfer_web_app" {
                identity_provider_details { identity_center_config { ... } } }

  Issue 2 — Terraform schema error: target_account_id not supported
  ─────────────────────────────────────────────────────────────────────────
  Cause   : aws_ssoadmin_account_assignment uses target_id, not target_account_id
  Fix     : Renamed target_account_id → target_id

  Issue 3 — IAM Identity Center returns empty list (plan error)
  ─────────────────────────────────────────────────────────────────────────
  Cause   : aws_region was set to us-east-1 but Identity Center was enabled
            in ap-southeast-1 (Singapore)
  Fix     : Updated aws_region = "ap-southeast-1" in terraform.tfvars

  Issue 4 — Permission set name too long (> 32 characters)
  ─────────────────────────────────────────────────────────────────────────
  Cause   : "${var.project_name}-TransferWebAppAccess" = 38 chars
  Fix     : Changed to hardcoded "TransferWebAppAccess" (20 chars)

  Issue 5 — "You do not have access to this application"
  ─────────────────────────────────────────────────────────────────────────
  Cause   : User was created and assigned a permission set, but was NOT
            assigned to the Transfer Family Web App SSO application itself.
            The web app registers as a separate SSO application in Identity
            Center (application_arn). Users must be assigned to it explicitly.
  Fix     : Added aws_ssoadmin_application_assignment resource using
            aws_transfer_web_app.main.identity_provider_details[0]
              .identity_center_config[0].application_arn

  Issue 6 — "There is an issue with the application setup" (S3 Access Grants)
  ─────────────────────────────────────────────────────────────────────────
  Cause   : S3 Access Grants was not configured. Transfer Family Web App
            requires S3 Access Grants to determine what each user can access.
  Fix     : Added:
            - aws_s3control_access_grants_instance (linked to Identity Center)
            - aws_iam_role + policy for Access Grants location
            - aws_s3control_access_grants_location (s3://bucket/*)
            - aws_s3control_access_grant per user (DIRECTORY_USER, READWRITE)

  Issue 7 — S3 Access Grants resource names wrong (aws_s3_* vs aws_s3control_*)
  ─────────────────────────────────────────────────────────────────────────
  Cause   : S3 Access Grants is part of S3 Control service, not S3 service.
            Resources are aws_s3control_*, not aws_s3_*
  Fix     : Renamed:
            aws_s3_access_grants_instance  → aws_s3control_access_grants_instance
            aws_s3_access_grants_location  → aws_s3control_access_grants_location
            aws_s3_access_grant            → aws_s3control_access_grant

  Issue 8 — S3 Access Grant creation failed (invalid prefix format)
  ─────────────────────────────────────────────────────────────────────────
  Cause   : location_scope = "s3://bucket/" (trailing slash) caused S3 Access
            Grants to treat it as an object path, not a bucket prefix
  Fix     : Changed to "s3://bucket/*" (trailing wildcard)

  Issue 9 — "There is an issue with the application setup" (wrong IAM actions)
  ─────────────────────────────────────────────────────────────────────────
  Cause   : Three wrong IAM configurations (all caused the same user-facing error):

    a) Web App role trust policy missing sts:SetContext
       Had    : Action = "sts:AssumeRole"
       Fixed  : Action = ["sts:AssumeRole", "sts:SetContext"]

    b) Web App role permissions used wrong S3 Access Grants actions
       Had    : s3:ListAccessGrants, s3:ListAccessGrantsLocations
       Fixed  : s3:ListCallerAccessGrants, s3:ListAccessGrantsInstances

    c) Access Grants location role trust policy used sts:SetSourceIdentity
       Had    : Action = ["sts:AssumeRole", "sts:SetSourceIdentity"]
       Fixed  : Action = ["sts:AssumeRole", "sts:SetContext"]

  Issue 10 — "There is an issue with the application setup" (missing CORS)
  ─────────────────────────────────────────────────────────────────────────
  Cause   : S3 bucket had no CORS configuration. Without CORS, the browser
            blocks all cross-origin requests from the web app to S3.
  Fix     : Added aws_s3_bucket_cors_configuration with AllowedOrigins set
            to the exact Transfer Family Web App URL (no trailing slash).
